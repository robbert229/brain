# Use go-oidc and oauth2 for OpenID Connect protocol mechanics

**Status**: accepted (supersedes spec 002 research decision D1)

The daemon's OpenID Connect relying-party mechanics — discovery validation, JWKS fetch and key rotation, ID-token signature verification, standard-claim checks, PKCE, and token exchange — are implemented on `github.com/coreos/go-oidc/v3` and `golang.org/x/oauth2` rather than hand-rolled on the standard library. Spec 002 originally chose a stdlib-only implementation (research D1) because the `tools/oidcverify` spike proved the narrow flow with zero dependencies; revisiting that choice, the hand-rolled code owned exactly the security-critical edge cases (algorithm handling, kid selection, audience parsing, timing rules) where subtle bugs become vulnerabilities, and a hand-rolled implementation must stay correct against every provider change forever. The libraries are the de facto standard for this surface (Kubernetes, Dex, Gitea) and their transitive tree is small (`go-jose` for JWS). braind keeps the parts that are policy, not protocol: the provider facade and health bookkeeping behind `/status`, endpoint-origin hardening beyond library defaults, nonce comparison, the coarse error vocabulary that keeps token material out of logs (FR-009), and the in-memory session, transaction, CSRF, and role layers. `tools/oidcverify` remains a dependency-free independent verifier used to check providers against the specification.

See [OIDC Sign-In and Role Access](../../specs/002-oidc-access/spec.md) and [ADR-0005](0005-oidc-group-based-roles.md).
